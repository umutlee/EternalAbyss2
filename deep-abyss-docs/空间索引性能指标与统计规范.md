# 空间索引性能指标与统计规范
版本: 1.0
日期: 2025-08-28
作者: CodeBuddy

目标
- 统一 SpatialIndex 指标口径与采集时机，指导性能分析与回归测试。
- 提供阈值建议与测试协议，支撑 CI 与本地验证。

一、指标定义（运行时类: SpatialIndexPerformanceStats）
- TotalQueries (long): 累计查询次数（自进程启动以来）
- FrameQueries (int): 当前帧内查询次数（每帧重置）
- AverageQueryTime (float, 秒): 平均查询耗时 = totalQueryTime / TotalQueries
- ObjectCount (int): 当前索引内对象数量
- PendingOperations (int): 待处理的插入/更新/移除队列长度之和

二、采集时机与实现备注
- UpdateQueryStats(float queryTimeSec) 在以下入口被调用：
  - QueryRange(center, radius)
  - QueryBounds(bounds)
  - QueryNearest(position)
  - QueryKNearest(position, k)
- 计时来源: Time.realtimeSinceStartup（开始/结束差值）
- 每帧重置:
  - UpdateService/Update 末尾将 FrameQueries 重置为 0
- 快照类型:
  - SpatialIndexPerfSnapshot 为旧版快照结构（序列化用途），避免与运行时类名冲突，不再作为唯一来源。

三、建议阈值（移动设备）
- 平均单次查询耗时（AverageQueryTime）
  - 目标: ≤ 0.0005 s（0.5 ms）
  - 警戒: 0.0005–0.0015 s（0.5–1.5 ms）
  - 告警: > 0.0015 s（>1.5 ms）
- 帧内查询次数（FrameQueries）
  - 目标: 常规 < 200；尖峰 < 500
- 对象规模（ObjectCount）
  - 目标: 常驻 5k 内；尖峰 20k 需降级策略（缩半径、分批查询）

四、测试协议（无场景资产）
- PlayMode 冒烟：Assets/DeepAbyssHive/Tests/PlayMode/SpatialIndexSmokeTest.cs
  - 构造 Bounds(1000^3) 世界 → 批量 AddObject → 执行 QueryRange/QueryBounds/QueryNearest/QueryKNearest/IsPositionOccupied
  - 断言: 结果数量合理；stats.TotalQueries 递增；FrameQueries 在 Update 后归零；AverageQueryTime ≥ 0
- 规模化回归（建议后续扩展）
  - N ∈ {1k, 5k, 10k, 20k} 随机分布 → 固定 10 次 QueryRange(半径=R) 采样 → 记录平均/最大耗时
  - 产出 CSV：N, R, mean, p95, p99, queries/sec
- 执行方式
  - Unity Test Runner（PlayMode）直接执行
  - CI: -runTests -testPlatform playmode -testResults ./test-results.xml

五、仪表盘与记录
- 每次测试收集 stats 并打印到日志（可解析的 JSON 行）
- 建议以日期/分支维度存储结果，便于回归比较

六、常见问题
- 为什么 AverageQueryTime 为 0？
  - 未触发任何查询；或被重置后仅进行少量查询，注意采样窗口
- 为什么 FrameQueries 长期高？
  - 每帧多次查询但未调用 Update/UpdateService；确保服务接入生命周期函数
