# 依赖关系图 v0.1（核心Manager交互）
版本：v0.1  
修改日期：2025-08-11

## 说明
- 本图用于标注当前与计划中的模块交互点，指导内部重构时的边界控制
- 不引入对外API变更，仅描述调用方向与职责

## 主要模块
- BuildingManager（建筑）
- CreepManager（菌毯）
- GameManager（生命周期/调度）
- TerrainManager（放置/阻挡/高度采样）
- SpatialIndex（ISpatialIndex<T>）
- UI/HUD（展示与交互入口）
- Save/Load（序列化）
- UnitManager（单位，间接受影响）
- Resource/BioEnergy（尚未实现，预留）

## 交互关系（现状与计划）
- GameManager → BuildingManager / CreepManager
  - 职责：Initialize/Update/FixedUpdate/LateUpdate/Pause/Resume 的统一调度

- BuildingManager → SpatialIndex
  - 现状：插入/移除建筑的空间包围盒，用于快速查询
  - API：ISpatialIndex<BuildingData>.Insert / Remove

- BuildingManager ↔ TerrainManager（计划增强）
  - 职责：建造放置校验、阻挡与高度采样
  - 计划：IsValidPlacement 在 requiresCreep 校验前增加地形验证

- BuildingManager ↔ CreepManager（计划增强）
  - 职责：建造需要菌毯时校验覆盖度；建筑提供菌毯扩张半径
  - 计划调用点：
    - BuildingManager.IsValidPlacement(..., requiresCreep: true)
      → CreepManager.HasCreepCoverage / GetCreepStrength
    - CreepManager 可根据 BuildingManager.GetCreepExpansionRadius 提升局部密度（订阅/轮询）

- BuildingManager → UI/HUD
  - 职责：生产队列、研究状态、升级进度的可视化
  - 通道：数据拉取（GetBuildingData）、事件后续再扩展（保持API不变）

- BuildingManager ↔ Save/Load
  - 职责：BuildingData、ProductionQueueItem、ResearchItem 的序列化/反序列化
  - 约束：字段名/类型保持稳定

- UnitManager ↔ SpatialIndex（间接影响）
  - 职责：单位与建筑的空间关系查询（进入范围、互动点）
  - 影响控制：仅通过 SpatialIndex 进行解耦，不直接依赖 BuildingManager

- Resource/BioEnergy（预留）
  - 未来：建筑的 BioEnergyConsumption / Generation 与资源系统对接
  - 现状：无直接依赖，保持字段存在以便接入

## 边界控制与阶段性目标
- 阶段1（当前）：只做 Building/Creep 内部拆分与实现优化；外部API不变；通过特性开关渐进接入
- 阶段2：补充与 TerrainManager 的放置校验与高度采样；增加与 CreepManager 的放置/扩张联动
- 阶段3：接入资源系统与UI事件（如有），在不改签名前提下新增内部事件或适配层
